## 目标

用户想让她「看视频画面（不只是文字）」时，`bili.watch` 工具新增 `see=true`：
抽关键帧 → 现有 opencode-go 网关（deepseek-v4.1-flash 多模态）描述画面 → 描述文本进入材料/回复管道。
不改变任何读写边界：仍是纯读 B 站 + 自家网关；无新增平台写操作。

## 设计要点

- 抽帧在宿主侧不引入新进程模型：直接调用容器内自带 `ffmpeg 7.1.5-0+deb13u1`（已探测存在）。
- 视觉请求走 BiliAPI 新增的普通 POST 通道（不记配额、不走 B 站风控码）。
- `see=true` 失败永远降级：`{"present": false, "reason": ...}`，不影响 watch 主体成功。

## 探测结论（容器内 m27_bili_see_probe.py）

1. opencode-go 视觉输入链路通：64×64 JPEG 探测返回 `content="红色"`，`reasoning_content` 真实描述了图片
   → deepseek-v4.1-flash 多模态确认；响应结构 `{role, content, reasoning_content}`。
2. 容器自带 ffmpeg 7.1.5-0+deb13u1（宿主机没有——抽帧必须发生在容器进程里，
   即 tool_loop 在容器内执行时才可用；seer 不可用时自动降级）。
3. 匿名 playurl 通：`GET /x/player/wbi/playurl?bvid&cid&qn=32&platform=html5&high_quality=0`
   → code 0，11s 视频 821KB mp4（upos CDN URL，需 Referer 头）。
4. 视觉请求体：`messages[0].content=[{type:text},{type:image_url,image_url:{url:"data:image/jpeg;base64,…"}}]`。

## 实现

### 新文件

- `digital_life_host/bili_see.py` — `BiliSee`（构造/配置/available/describe）+ `configured_bili_seer`。
  - 配置 `config.bilibili.see`：`frames`(3-8)、`scale`(240-960)、`max_chars`(600-6000)、
    `model`/`api_base`/`key`（缺省从 data_root 上层 `cmd_config.json` 的 provider_sources[0] 自动取）。
  - `describe(port, bvid)`：video_info → play_url(quality=32) → 均匀采样偏移（≤6s 用 0.5s 间隔，
    否则均匀铺到结尾前 1s）→ ffmpeg 每帧独立抽（`-headers "Referer: https://www.bilibili.com/\r\nUser-Agent: …"`
    `-vf scale=480:-2 -q:v 7`，单帧失败跳过，整段超时 90s）→ 视觉请求 → `choices[0].message.content`。
  - `configured_bili_seer(config, data_root)`：模块关 / 显式 `enabled: false` / 无网关凭据 → None（降级）。

### BiliAPI 扩展（digital_life_core/bilibili/bili_api.py）

- `play_url(video, *, quality=32)`：`_get_json` `/x/player/wbi/playurl`，缺 bvid/cid 或空 durl → BiliError；
  返回 `{url, size}`。
- `post_json(url, payload, *, timeout=120.0, headers=None)`：普通 POST，不记配额不走风控码；
  HTTP≥400 / 非 JSON / 非 dict → BiliError。

### bili_tools 扩展（digital_life_core/conversation/bili_tools.py）

- `BiliWatchTools(factory, seer=None)`；schema 加 `see: boolean`；
  `_material(..., see=False)`：video 分支末尾 `if see: payload["sight"] = await self._sight(port, bvid, video)`。
- `_sight`：seer 缺失 → `{"present": False, "reason": "seer_unavailable"}`；
  seer 抛错 → `{"present": False, "reason": str(error)[:120]}`（validate 的 sight 形状二选一，两种都合法）；
  成功 → `{"present": True, "frames"≤16, "offsets", "description"[:3000]}`。
- INSTRUCTION 首句加：用户想让她看画面（不只是文字）时传 `see=true`。

### 接线链（bili_seer 全链传参）

`controller.py:477` / `multi_controller.py:980`（内部 `configured_bili_seer(self.config, self.data_root)`）
→ `application.py` → `staging.py` / `staging_bootstrap.py` / `multi_session.py` → `tool_loop.py:157/189`
→ `BiliWatchTools(bili_factory, bili_seer)`。

## 探测联调修复链（生产容器实测发现，均已修复提交）

1. `dd5f62d`：`cmd_config.json` 的 model 不在 provider_sources[0].model（为 None），
   而在顶层 `provider[].model`（按 `provider_source_id` 关联）→ `_gateway_from_runtime` 改按映射取；
   新增测试 `test_seer_falls_back_to_runtime_gateway_with_provider_level_model`。
2. `2514816`：opencode-go 网关要求 `x-opencode-session` 头（缺它 400 MissingSessionID）→
   BiliSee 生成 per-instance UUID 会话头。
3. `96b8ef1`：网关要求 `Authorization: Bearer <key>`（缺它 401）→ 请求头带上网关密钥。
4. `d7469bc`：单帧请求正常，但 6 帧 + prompt 在 max_tokens=1200 下 reasoning 烧尽
   （finish=length、content 空）→ 预算提到 2400，且 content 空时用前 3 帧重试一次（1600）。
5. **最终探针 PROBE-OK**：BV1BFySzaEP8 → 6 帧全部抽出
   （offsets=[0.5,2.3,4.1,5.9,7.7,9.5]，每帧 22-35KB JPEG）→ 视觉描述完整：
   逐帧描述了 Q 版蓝发鲸鱼女仆的动作变化，并正确读出画面花字「狗熊哆嗦毛」。

## 真实环境验收项（待用户协助）

1. QQ 私聊问她「你能看视频画面吗」→ 她应答包含"看画面/see"相关能力话术。
2. 让她看一个短视频（如 BV1BFySzaEP8）并带画面描述：她回复应引用画面内容（不只标题/简介/热评）。
3. 观察回复时间：抽帧+视觉请求合计应在 1-2 分钟内（超时则看 seer reason 降级）。
4. 容器 `docker logs astrbot-dl | grep -i bili` 应无 BiliError 堆积；quota.json 不应出现 ban
   （视觉请求不记配额）。
