# M2.6d 看画面管线升级：变化选帧 + 单张拼图

## 背景

M2.6c 的多帧直传在实践中暴露两个问题：

1. 该网关的模型先烧 reasoning 再给 content，6 张独立图时 reasoning 长度波动大，
   预算被烧尽就返回空描述（`finish=length`），需要降帧兜底救场；
2. 每帧独立计费，6 张 480px 图约 558 token，观感成本高。

对照 dsh-see-now（Apache-2.0）源码逐行分析后确认：它的核心优势是
「变化量选帧 + 单张拼图 + 官方 patch token 公式定画布」，这正是我们缺的。

## 实现（提交 592ad4c + d14ac9a）

`digital_life_host/bili_see.py` 重写为三段式：

1. **探针抽帧**：均匀抽 `probe`（默认 12，夹取 6–24）张 96px 低分辨率候选帧
   （HTTP range 定点，不整段下载）。
2. **变化量选帧**：每帧降采样成 64×36 HSV 网格，与前一帧做色相加权绝对差
   （0–255，照搬 dsh-see-now `cuts.js` `scorePair` 口径：hue 环形距离
   `min(dh, 255-dh)` × `min(sat, sat_prev)` 权重）；首帧必选 + 变化尖峰按
   分数贪心入选（同分取更早的帧；两帧间保 `duration/(frames*2)` 最小间隔，
   避免全挤在一个切点）。无 Pillow 时退化成均匀选帧。
3. **单张拼图**：入选帧各缩放/pad 到格子尺寸，ffmpeg hstack/vstack 拼成
   一张网格图；画布尺寸由官方 DeepSeek patch token 公式反推
   （14px patch → 42px token 格 → `tokens = rows×(cols+1)+2`，
   `fit_sheet()` 在 `see.sheet_tokens` 预算（默认 420，夹取 160–1000）内
   14px 步进取最大画布）。整幅拼图走一次视觉请求（max_tokens=4000）。

兜底链：拼图帧不足/拼图失败/拼图空描述 → 独立帧 `[3 帧 2600, 1 帧 1800]`
降帧梯子（重抽 480px，不再用 96px 探针图）→ 全空才抛 `BiliError`。

其他：

- 新增配置项：`bilibili.see.probe`、`bilibili.see.sheet_tokens`
  （去掉 `scale`，格子尺寸由 token 预算推导）。
- `BiliSee` 构造时清扫 `/tmp/bilibili-see-*` 超过 1 小时的孤儿临时目录
  （进程被杀残留；正常流程 `TemporaryDirectory` 用完即删）——**视频与帧
  均不占服务器持久空间**。
- 结果结构不变：`{"present", "frames", "offsets", "description"}`，
  核心侧（bili_tools/bili_events）零改动。

## 测试

- 新增 `tests/test_bili_see_pipeline.py`（14 用例）：
  官方公式对拍（1036×583=366、1066×600=407）、预算封顶与计费地板、
  `fit_sheet` 预算内最大画布、色相回绕/去饱和、首帧+尖峰选帧、
  最小间隔、describe 接线、ffmpeg 拼图烟雾（容器内真跑 480×270 画布）。
- bili 全家（本地）：49 passed + 1 skipped（烟雾本地无 ffmpeg）。
- 容器批 `/opt/m27_see2`（11 文件）：110 passed + 3 failed，
  失败 = owner_tools slang 撤回竞态 + image_prompt settings 计数
  （HEAD 基线同败）+ 拼图烟雾首跑夹具 hsl 参数越界（修后 14 passed）。
- 邻近回归（本地）：proactive_contacts + contact_scheduling +
  bili_curiosity + storage_pool = 104 passed + 6 subtests。

## 生产验证

探针 BV1BFySzaEP8（11s 竖屏舞蹈视频）：

```
picked=6 at 0s、2s、6s、8s、8s、10s
拼图成功 1358x504 (~410 tok) frames=6 finish=stop
```

一次视觉请求出完整描述，逐帧动作连贯准确，读出画面花字「明の大肥鲸」。
对比 M2.6c 同视频：同样 6 帧，token 从 ~558（6 张独立图）降到 ~410
（单张拼图），且不再依赖降帧兜底。

## 真实环境验收项

1. QQ 里让小鲸鱼「看一个长视频的画面」（>5 分钟），确认描述覆盖开头/中段
   而不是只讲前 10 秒；
2. 看一个有明确转场的视频，确认选帧落在转点附近（描述出现「切换镜头」类表述）；
3. 连续让她看 3 个视频，观察日志 `[bili][see] 拼图成功` 是否每次出现，
   `bilibili-see-*` 临时目录是否用完即清（`docker exec astrbot-dl ls /tmp`）。
