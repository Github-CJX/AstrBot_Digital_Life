# M1.1 验证记录：生图身份一致性（2026-11-25）

本记录对应 M1 之后的第一个补丁批次（M1.1）。起因是 M1 宿主验收期间发现的真实缺陷：角色形象改造后，模型仍然用纯文生图（`image.generate`）凭文字描述画自己，产出与设定图无关的图（当时画成「橘粉色胖鱼」）；身份参考素材虽已注册，却既没进提示词、也没进工具参数。

结论：三个代码补丁 + 一个测试文件，行为已在容器内实测；三个已知失败与本次补丁无关（基线同样失败，证据见第 4 节）。

## 1. 缺陷链（三个断点）

1. **提示词阶段读不到素材**：`digital_life_host/core_reply_tools.py` 里 `ensure_image_access` 只在 `media_enabled` 分支调用，而 `inject_core_image_prompt` 无条件执行；私聊工具档案非 `full` 时从未签发 `extension.tool.invoke`，`ReferenceAssetService.prompt_material()` 的 `_admit`（`digital_life_core/references/service.py:76`）抛 `scope_not_granted`，身份素材 id 因此从未进入本轮上下文。
2. **工具说明把自拍判给 generate**：`_PURPOSES["image.generate"]` 原文把「无身份锚点的自拍」列为适用场景，模型于是合理选择纯文生图，`reference_inputs=[]`。
3. **拦截被当作「结果未知」**：即使加了「必须带 identity 参考」的拦截，抛出的 `TaskError` 也会被 `core_reply_tool_execution.py:222` 包成 `state=unknown / effect=unknown / retry_disposition=external_effect_unknown`，模型据此回答「卡住了，结果还没确认」，不会改参数重试。

## 2. 补丁内容（3 个文件）

### `digital_life_host/core_reply_image_prompt.py`

- `_PURPOSES["image.generate"]` 改为：仅用于与本角色无关的全新画面；画角色本人（自拍、画像、长相、穿着）一律不要使用此工具，改用 `image.edit` 并填 identity 参考；修改本轮附图/引用图/刚发出的图时也不要使用。
- `inject_core_image_prompt()` 的 `except` 分支新增兜底：`prompt_material` 授权失败时，直接用 `owner.assets.list(owner.owner(context), role=ReferenceRole.IDENTITY)` 读仓库拿 `fallback_ids`，写入 `session.state["_image_reference_material"]`（供工具层注入），并把「本轮身份锚点：reference_ids=[…]，reference_indices=[]，reference_roles=["identity"]」并入 `_turn_notes["image"]`。
- **不改系统提示词**：既有测试（`test_core_reply_image_prompt.py`）要求系统提示词逐轮稳定、不得出现素材 id，逐轮信息只走本轮用户消息（`inject_core_turn_notes`）。兜底因此只写 turn note 与 session state。

### `digital_life_host/native_extensions/__init__.py`

- 新增 `_require_identity_reference(invocation)`：`image.generate` 且参数里没有 `reference_ids`、而角色确有 identity 素材时，抛 `TaskError("identity_reference_required", …)`，报错文案直接给出可用的 `reference_ids` / `reference_indices` / `reference_roles=["identity"]` 与「prompt 只写动作镜头场景光线」的改写要求。
- `invoke()` 中在派发前调用该守卫，命中 `_IMAGE_PREFLIGHT_LEASE_CODES` 的码则走既有 `_preflight_failure()`，返回 `state=failed / effect=not_committed`（生图请求并未发出，可安全重试），不再落到 unknown。
- `_IMAGE_PREFLIGHT_LEASE_CODES` 追加 `"identity_reference_required"`。

### `digital_life_core/conversation/tool_failures.py`

- `_INPUT_CODES` 追加 `"identity_reference_required"` → `retry_disposition_for` 对 failed 状态返回 `input_invalid`。
- `failure_guidance` 新增该码的 `reason`（画角色本人不能用纯文生图，本次未发起远端生图）与 `next_step`（立刻改用 `image.edit` + identity 参考；prompt 只写动作、镜头、场景、光线、情绪，不要重复外貌，也不要把她画成鱼或其它物种）。

### 撤回的改动（记录以免重复踩坑）

`digital_life_host/core_reply_tools.py` 里曾把 `ensure_image_access` 提前到私聊无条件执行；实测会让 `test_multi_image_access` 的 `capability_authorizations` 从 3 变 6（多签发一轮授权），而身份锚点已由上面的兜底解决，故该文件回基线，**不在本批 diff 内**。

## 3. 新增测试

`tests/test_native_identity_reference_guard.py`（7797 B）四组：

1. `IdentityReferenceGuardTests`：`identity_reference_required` 在预检码表内；无 `reference_ids` 且有 identity 素材时守卫抛 `TaskError`（码正确、文案含素材 id 与 `image.edit`）；已带 `reference_ids` 或角色无 identity 素材时放行；`invoke()` 把该码映射为 `_preflight_failure` 返回值而非 unknown。
2. `IdentityFailureGuidanceTests`：`retry_disposition_for("identity_reference_required", "failed") == "input_invalid"`、`"unknown"` 时为 `external_effect_unknown`；`failure_guidance` 的 `next_step` 含 `image.edit` / `identity`，`reason` 含「未发起远端生图」。
3. `PromptFallbackTests`：`prompt_material` 抛 `scope_not_granted` 时，`session.state["_image_reference_material"]` 含身份素材、turn note 含素材 id、系统提示词不含素材 id。
4. `ImageProvisionOrderTests`：用 `ast` 解析 `core_reply_tools.py`，断言 `ensure_image_access` 出现在 `inject_core_image_prompt` 之前（守住既有调用顺序，防止再次前移签发）。

## 4. 测试证据（容器 `astrbot-dl`，pytest 9.2.0）

命令（部署目录 `/AstrBot/data/plugins/astrbot_plugin_digital_life`）：

```
docker exec -i -w /AstrBot/data/plugins/astrbot_plugin_digital_life astrbot-dl \
  python -m pytest -q -p no:cacheprovider --tb=no \
  tests/test_native_identity_reference_guard.py tests/test_core_reply_image_prompt.py \
  tests/test_native_extensions_registry.py tests/test_native_image_references.py \
  tests/test_r3_image_failure_matrix.py tests/test_r2_image_error_semantics.py \
  tests/test_image_edit_fallback_and_errors.py tests/test_multi_image_access.py
```

结果：**3 failed, 157 passed, 70 subtests passed in 140.85s**（含本批全部新增用例通过）。

三个失败项：

- `test_core_reply_image_prompt.py::test_without_image_tools_no_preferences_or_references_are_read`
- `test_multi_image_access.py::test_first_admitted_context_exposes_and_executes_native_image_tool`
- `test_multi_image_access.py::test_request_injection_repairs_image_defaults_missing_during_admission`

基线对照：把 `digital_life_core/conversation/tool_failures.py`、`digital_life_host/native_extensions/__init__.py`、`digital_life_host/core_reply_image_prompt.py` 三个文件替换为 `git show HEAD:` 原文后，仅跑 `test_multi_image_access.py` + `test_core_reply_image_prompt.py`，结果同样是这 3 failed / 27 passed。→ 这 3 项是 M1 提交时既有的失败（授权行数与降级路径相关），与本批补丁无关，记为已知基线失败，未在本批修复。

`py_compile` 三文件在容器内 Python 3.12 下通过（宿主 Python 3.6.8 会误报 `future feature annotations is not defined`，不可用于本仓库校验）。

## 5. 与宿主运行时相关的事实（不在仓库内，记录于服务器文档）

- 生图端点为 OpenAI 兼容的 ephone（`gpt-image-2.5-dev`），`image.generate` / `image.edit` ready，`image.mask_edit` 不支持（openai 兼容平台只声明 generate/edit）。
- 工具超时：`cmd_config.json` 的 `agent_runner.config.misc.tool_call_timeout` 120 → **600**；插件 `runtime.turn_timeout_seconds` 300 → **600**。原因：该端点图生图实测 213 s，超过 AstrBot 默认 120 s 工具超时，会被判 `execution timeout after 120 seconds`。
- 角色档案与参考素材：`role_profile`（汐）、`relationship_profile`、`photo.reference.enabled=true`、`image-materials/references/upload` 注册三视图（`roles=["identity","outfit","style"]`，`usage.base_identity=true`）。

## 6. 待复核

- 真实 QQ 单聊再发一轮「画你自己」，确认（a）模型改用 `digital_life_core_image_edit` 且带 identity 参考；（b）不再出现 `核心生图参考资料暂不可用 code=scope_not_granted` 影响生成结果；（c）不再出现 `state=unknown` 的「结果还没确认」话术。
- 若 `image.generate` 被守卫拦下，报错应带 `retry_disposition=input_invalid`，模型应自行改调 `image.edit`。
