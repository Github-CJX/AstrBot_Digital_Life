## 3. 下一步 M1 宿主验收清单
1. 创建全新 AstrBot 测试实例（>=4.27.2，满足依赖与 Python 版本约束），先保存测试数据和配置备份。不同时安装原插件。
2. 将开发包解压至 `data/plugins/astrbot_plugin_digital_life/`（以部署环境实际目录为准）；确认插件目录、metadata、入口在同一层。按 AstrBot 版本的正常安装依赖和加载流程启动。不要覆盖生产目录。
3. 检查启动日志：无导入/配置/路由/SDK 异常；仅一个 Star；默认数据根在自己的 plugin_data 目录，不读取旧插件数据库。验证页面可访问、资源加载、角色绑定、私聊群聊、记忆、日程、睡眠和重启。
4. 使用隔离测试模型及非生产身份；外部能力先关闭（M1 尚未落实 M2 开关）；不测试实际设备或主动发布。记录 token 和任务数。
5. 禁用、启用、重载、卸载，再检查后台任务、注册/路由、日志 handler 和 sys.modules。不得有重复或旧状态残留。
6. 运行原有完整测试及 JS 检查，修复失败后记录新的 commit。固定各参考框架 SHA 后，才关闭 M1；允许并行开展 M2 只读依赖盘点。
7. 回滚：停止测试实例，只移除本次测试安装，不删除生产数据；Git 回滚到初始快照用于对照，绝不将初始快照覆盖新版数据根。
