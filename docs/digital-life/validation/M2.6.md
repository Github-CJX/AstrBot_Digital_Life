# M2.6 验证记录：bilibili 只读好奇模块（bili.watch 工具 + 每日好奇唤醒主动接触）

范围：M2 之后的第一个「可选启用」新模块。默认关（`module_gates` 的 `bilibili` 可选门），
零写操作（不发私信、不发评论、不点赞），只做公开元数据 + 字幕读取，经既有 provider
管道由角色消化，见闻进生活账本，QQ 私聊分享；自主唤醒沿用 bili_whale（MIT，见
`digital_life_core/bilibili/LICENSES/bili-whale-MIT.txt` 与 `NOTICE.md`）的生物钟行为模型。

## 做了什么

### 新增文件
- `digital_life_core/bilibili/`：vendored bili_whale 精简移植（MIT 原件为
  `D:\opc-work\bili_whale\`，服务器 `/opt/bili_whale`）。`bili_api.py`（WBI 签名、
  search/recommend/video_info/subtitles/hot_comments/danmaku_hotspots，纯读端点）、
  `traffic.py`（TrafficGuard：请求间隔 + 按小时/天记账 + 412/-352 风控码熔断）、
  `quota.py`/`state.py`（QuotaStore，持久化 `bilibili/quota.json`）、`errors.py`、
  `models.py`、`util.py`。写侧（send_dm/post_comment）未移植。
- `digital_life_core/conversation/bili_tools.py`：`bili.watch` 工具。无 BV →
  `port.search(keyword, page_size=12)` 候选列表（mode=candidates）；带 BV →
  video_info→subtitles→hot_comments(6)→danmaku_hotspots(8 桶)（mode=video）；
  工厂每次调用新建、finally close；BiliRisk→`bili_watch_rate_limited` 等错误码映射。
- `digital_life_core/proactive/bili_events.py`：`BiliWatchContactEvents` 每日好奇
  唤醒生产器。DEFAULT_CURIOSITY {wake_start_hour:9, wake_end_hour:23,
  skip_chance_percent:30, max_per_day:1, min_gap_hours:6}（`bilibili.curiosity` 可
  覆盖，curiosity_settings 夹取）；CuriosityState 原子写
  `bilibili/curiosity.json`（坏 JSON 返回 {}）；select（retry 窗口 30min、唤醒窗、
  digest 确定性日跳过、max_per_day/min_gap、jitter 计划时刻）→ prepare（factory→
  start→recommend(24)→去重 cap 8→state 记 wakes[-8:]+last_event→publish
  SourceRecord(owner=`proactive.bili_curiosity`，payload 带 _receipt)→Thought→
  ContactIntent("environment")→marker{event_id,settings_hash,source}）；
  _validate_source/validate 对 settings_hash、last_event、窗口与 reference 重建，
  失败抛 `contact_bili_changed`/`contact_bili_invalid`。
- `digital_life_host/bili_watch.py`：`configured_bili_factory(config, data_root)`
  （模块门 + `bilibili.cookie` 解析）与 `configured_bili_settings(config)`。

### 接线
- `module_gates.py`：`bilibili` 进可选组（默认关）。
- `tool_loop.py`：注册 `bili.watch` 工具目录（PRIVATE/GROUP 可见）。
- `scheduling.py`：ContactSchedule ctor 三参、`bili_events` 装配（factory None 则
  None）、origin 校验 `bili_event` 分支（缺 producer→`contact_bili_unavailable`）、
  `_plan` 的 `bili_pending` 分支（news 之后）、`_run` prepare 分发（失败记
  `contact_bili_unavailable` source_preparation）、close 收尾。诊断 synthetic 表
  有意不含 bili（v1 不进诊断套件）。
- `host/application.py`：bili_settings/bili_state_path 透传 ContactSchedule。
- `controller.py`/`multi_controller.py`/`multi_session.py`：装配三参
  （`bili_settings=configured_bili_settings(self.config)`、
  `bili_state_path=Path(data_root)/"bilibili"/"curiosity.json"`）。
- `prompts.py`：`evidence_materials` 的 `_receipt` 剥离白名单加
  `proactive.bili_curiosity`。
- `material_pool.py`：SOURCE_CATEGORIES/SOURCE_LABELS/THOUGHT_ORIGINS/投影注册。
- BiliAPI 生命周期：factory 不建 aiohttp session，`bili_events.prepare` 统一
  `await port.start()`（BiliAPI.start 幂等）后再读，finally close。

### 测试
- `tests/test_bili_watch_tool.py`：工具模式/错误码映射/生命周期
  （`test_real_port_lifecycle_starts_before_reading` 断言 start→…→close 顺序）。
- `tests/test_bili_host_factory.py`：模块门、cookie 解析、settings 提取。
- `tests/test_bili_curiosity_events.py`：12 例（候选批投递 + origin/材料/无
  _receipt、失败重试不落账、重启后同日封顶、时钟门/窗口/跳过/max-per-day/min-gap/
  jitter、prepare 发布与 marker 校验、设置夹取、CuriosityState 内存/文件/坏 JSON）。

## 已知边界
- `bilibili` 模块默认关；开启仅通过 `digital_life_modules.json` 或环境门。
- `bilibili.cookie` 可选；无 cookie 也能看公开视频，只是字幕与推荐流更弱。
- 预算状态 `bilibili/quota.json`、好奇状态 `bilibili/curiosity.json` 均为 JSON 文件，
  不进 SQLite schema（无迁移）。
- 好奇重试窗（30min）在内存里，重启即失（保守方向：多睡一次）。
