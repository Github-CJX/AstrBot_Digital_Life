# M2.3 依赖解耦

M2 移除顺序第三步：把可选模块与待移除模块对宿主的**代码级依赖**拆开，使得开关关闭时
连实现包都不再被导入；关掉任何一项后不再产生外部 I/O，聊天与热重载照常。

需求来源：`doc/digital_life_M2_requirements.md`（保留 8 / 可选 6 / 移除 4）。

## 1. 目标与边界

| 边界 | 处理 |
| --- | --- |
| 生图可选，但历史附件必须保留 | 先把 `storage/compaction.py` 里对 `image_native.store` 的反向依赖解除，附件迁移逻辑下沉到 core |
| 米家 / 华为健康 与 手机 / 屏幕 必须拆分 | 不删 `reality` 包，只把 mihome 三条 import 挂到 mihome 开关上 |
| 关闭后无外部 I/O | 关闭时连接器、发布器、服务实例一律不构造 |
| 关闭后聊天与重载正常 | 上述路径全部走惰性导入，重开只需重启插件 |

## 2. 生图附件：反向依赖解除

新增 `digital_life_core/storage/artifact_blobs.py`（纯 core，无 host 依赖）：

- `FILE_MARKER = b"\x00PCNIMG1/"`：磁盘上已经存在的字节格式，名字与内容冻结；
- `marker_for(relative)` / `is_file_marker(value)` / `marker_path(value)`：标记的构造与解析，
  非法路径返回 `""`；
- `write_blob(media_root, content, *, media_type="")`：内容寻址落盘（`<前两位>/<sha256>.<ext>`，
  临时文件 + `os.replace`）；
- `offload_artifact_blobs(db_path, *, media_root, batch_size=64, table="artifacts")`：
  把内联 BLOB 批量搬成文件标记，返回 `{migrated, already_file_backed, bytes_offloaded}`；
- `count_inline_blobs(db_path, *, table="artifacts", column="data")`：体检计数。

`digital_life_host/native_extensions/image_native/store.py` 从 438 行降到 344 行：
`_store_media_bytes` / `_load_media_bytes` / `gc_unreferenced_media` 改为调用 core 实现，
`migrate_native_image_store_at()` 变成 15 行薄封装。

`digital_life_core/storage/compaction.py` 原来两处
`from digital_life_host.native_extensions.image_native.store import ...` 改为 core 实现——
这就是需求点名的反向依赖。

### 生图工具面：运行期求值，不能模块级定死

`native_extensions/__init__.py` 里生图动作集 `IMAGE_ACTIONS`、引用租约类型、结果处理器、
开关读取函数都在第一次用到时才导入：

```
def _image_surface():
    if not module_enabled("image"):
        return frozenset(), None, _disabled_image_result_handler, _disabled_image_settings
    from .images import IMAGE_ACTIONS, ImageReferenceLease, image_result_handler
    from .image_settings import read_image_settings
    return IMAGE_ACTIONS, ImageReferenceLease, image_result_handler, read_image_settings
```

配套 `_image_actions()`、`_image_error_type()`（关时返回占位异常类）。**踩过的坑**：第一版写成
模块级 `if module_enabled("image"): import ... else: IMAGE_ACTIONS = frozenset()`，
而 `tests/conftest.py` 的全功能 fixture 是 session 级 autouse（collection 之后才设环境变量），
模块 import 时读到 image=off，动作集永久为空，18 个生图用例全红。

## 5. 测试

新增 `tests/test_m2_module_decoupling.py`：

- `CommandImportTests`（6 例）：子进程干净环境里导入目标模块，断言被解耦的包不在
  `sys.modules`（`controller` ↛ `qzone_client`/`qzone_transport`；`multi_api`/`web_api` ↛
  `qzone_api`/`huawei_health.api`；`multi_session` ↛ `huawei_health.service`；`builtins`
  调用 `create_bundled_extensions` 后 ↛ `image_native`/`screen_provider`）。用子进程是因为
  同进程断言必然假阳性——别的用例早就 import 过了。
- `BlobOffloadTests`（4 例）：标记 roundtrip、`write_blob` 内容寻址幂等、
  `offload_artifact_blobs` 搬迁、缺表容忍。

容器内一次性容器跑 9 套件（模块开关 / 解耦 / 生图引用 / 身份守卫 / 生图失败矩阵 /
生图错误语义 / 编辑回退 / 多图访问 / 核心生图提示词）：

```
3 failed, 164 passed, 65 subtests passed in 174.25s
```

3 个失败是 M1.1 已确认的基线既有项（`test_multi_image_access` 两例 +
`test_core_reply_image_prompt::test_without_image_tools_no_preferences_or_references_are_read`），
与本次改动无关。
