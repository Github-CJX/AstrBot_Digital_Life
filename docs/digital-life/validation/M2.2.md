# M2.2 配置分节与页面入口随模块开关隐藏

2026-11-25。M2 需求文档给出的移除顺序第二步：注册/调度停止之后，做「配置和页面隐藏」。本步只做**可见性与路由面**收敛，不动实现、不删文件、不迁移数据。

## 1. 目标与边界

| 类别 | 模块 | 配置分节 | 页面入口 |
| --- | --- | --- | --- |
| 保留 | content / reality / together | 始终可见 | 始终可见 |
| 可选 | image | `quota` `image_review` `image.output` `wardrobe` `photo.reference` | 产出页生图面板 |
| 可选 | phone | `device.phone`（含 `/config/phone-connection`、`/config/phone-task` 路由） | 手机使用、手机端连接 |
| 可选 | screen | `screen` | 屏幕观察面板 |
| 可选 | workspace | — | 3D 小屋（管理后台保留） |
| 可选 | game / multi_role | — | 游戏面板 / 关系网入口 |
| 移除 | qzone | `qzone` | QQ 空间区块 |
| 移除 | live / mihome / huawei_health | 无独立分节 | 无独立入口 |

硬边界：分节与入口藏起来，不等于权限、数据、API 主体消失。`SECTIONS` 表、四个 `*Management` 类、页面资产、历史记录一律保留。

## 2. 实现

### 2.1 `digital_life_host/module_gates.py`

新增两张映射与四个判定函数，全部走既有的 `resolved()`（环境变量 > `digital_life_modules.json` > 默认）：

- `SECTION_MODULES = {"quota": "image", "image_review": "image", "image.output": "image", "wardrobe": "image", "photo.reference": "image", "screen": "screen", "device.phone": "phone", "qzone": "qzone", "content.authoring": "content", "library": "content"}`
- `PAGE_MODULES = {"workspace": "workspace", "room": "workspace", "multi_role": "multi_role", "game": "game", "phone": "phone", "screen": "screen"}`
- `section_visible(section)` → `module_enabled(SECTION_MODULES.get(section, ""))`；未登记的节落到空名，`module_enabled` 对未知模块返回 True，即「默认可见」。
- `visible_sections(names)` / `page_visible(page)` / `page_visibility()`。

### 2.2 `digital_life_host/configuration_api.py`

```python
if allowed_sections is None:
    names = tuple(SECTIONS)
else:
    ...
self.sections = {name: SECTIONS[name] for name in visible_sections(names)}
```

要点：

- 闸门在 `ConfigurationWebAPI.__init__`，**位于** `multi_api` 的三种白名单（`INSTALLATION_/TARGET_/GROUP_CONFIGURATION_SECTIONS`）之后 —— 白名单先收窄，模块开关再收窄，两者取交集。
- 关掉的节不只是列表里消失：`status` 不返回它、`/config/configure` 以 `configuration_request_invalid` 拒绝写入，`if "device.phone" in self.sections:` 分支连带 `/phone-connection`、`/phone-task` 两条路由一起消失。

### 2.3 `digital_life_host/page_api.py`

新增 `GET /astrbot_plugin_digital_life/page/modules`：

```json
{"modules": {"content": true, "image": false, ...},
 "pages": {"workspace": false, "multi_role": false, "game": false, ...},
 "hidden_sections": ["device.phone", "image.output", "qzone", "screen", ...]}
```

鉴权沿用同文件的 `_display_preferences_identity()`：必须是 Dashboard 登录用户（`api_key:` 拒绝）、必须是本插件名下的请求、不接受 query 覆盖、插件停止时返回 `staging_host_terminated`。

### 3.1 基线既有失败：`test_every_section_reads_with_its_own_scope_and_token`

首次进容器跑就红，报 `Items in the first set but not the second: 'device.phone'`。用 `git show HEAD:digital_life_host/configuration_api.py` 覆盖部署目录后单跑同一用例，**仍然失败**（`False is not true : device.phone`），确认与本步补丁无关，属两处按字面枚举的名单没跟上 `device.phone` 这个真分区：

1. `expected_sections` 硬编码清单缺 `device.phone`；
2. 组名前缀白名单缺 `device`（`digital_life_core/device/configuration.py:27 GROUP = "device.phone"`）。

两处均已补上并附注原因，改后该用例通过。

## 4. 页面接线

### 4.1 `pages/陪伴小屋/shell.js`

左栏是页面里唯一一份分组数据（左栏与「全部功能」浮层都读 `railGroups()`），所以过滤放在这里，两处一起收敛：

- `ITEM_MODULES = {phone: "phone", mobile: "phone"}` —— 只有登记过的条目受开关约束，其余条目始终可见。
- `setVisibility({modules, pages})` / `moduleVisible(name)` / `pageVisible(name)` / `snapshotVisibility()`。
- `railGroups()` 先按 `itemVisible(id)` 过滤条目，再把整组为空的组整组丢掉（不留只有标题的空壳）；`railHTML()` 改成消费 `railGroups()` 的结果，不再直接读 `RAIL_GROUPS`。
- 默认全开：读不到开关时 `moduleVisible()` 一律返回真——开关只收窄可见性，不能变成一个让页面空掉的新失败点。

### 4.2 `pages/陪伴小屋/app.js`

- 启动后 `loadModuleState()` 读 `GET page/modules`，落地到 `moduleState` 与 `window.CompanionModules`，再 `CompanionShell.setVisibility(...)`；模块集合有变化时补一次 `render()`。
- 预览/离线外壳里 `product.request` 不存在，直接跳过（不写控制台告警：那是正常形态，不是失败）。
- 三处可选面板的挂载闸门：手机向导 `if($('#phoneAdbWorkspace')&&moduleOn('phone'))`、游戏授权 `if(gameAccessHost&&moduleOn('game'))`、识屏授权与最近识屏 `screenAccessHost&&moduleOn('screen')`。

### 4.3 测试

新增 `tests/test_module_visibility.cjs`（node --test，8 例）：默认全开、关掉 phone 只收两项、保留模块条目不受影响、空组不渲染、`railHTML` 跟随、重复设置不重复通知订阅者、坏输入按全开、`app.js` 的读取与三处闸门有对表断言。

验证：`test_module_visibility + test_shell + test_navigation + test_lite_room_runtime + test_catalog_navigation + test_section_wiring` → **80 passed**。

仓库既有 `.cjs` 全量（1648 例）在本次改动前后都跑过：**改动前 33 failed / 1607 passed，改动后 25–27 failed / 1613–1615 passed，失败集合是同一批**（日历时间线、房间布置工作台、CSS 尺度审计、联系人权限等，多为按日期/时序的用例，逐文件单跑均为通过或与 HEAD 一致）。`test_room_editor.cjs` 单跑：改动前后都是 7 failed / 1 passed。

## 5. 部署与生效

- 覆盖四个 Python 文件 + 两个页面文件后**不需要重启容器**：页面是静态资产，浏览器刷新即取到新版；`configuration_api`/`page_api` 的分节表在 WebAPI 构造时求值，插件重载或容器重启后才串到后端。
- 线上开关文件仍是 `/opt/astrbot-dl/data/plugin_data/astrbot_plugin_digital_life/digital_life_modules.json`，当前内容 `{"modules": {"image": true}}`；也就是说**生图相关的五个分节与生图能力现在可用，其余可选模块的分节与入口默认不可见**。
- 关闭态自检：`GET /astrbot_plugin_digital_life/page/modules` 的 `hidden_sections` 应包含 `qzone/device.phone/screen`；左栏应只剩「专题配置」里除手机两项之外的条目。
